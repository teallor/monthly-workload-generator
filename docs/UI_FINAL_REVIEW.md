# v1.1 最终 UI 验收记录

日期：2026-06-30  
技术栈：Tkinter + ttk  
范围：仅UI层、窗口显示和EXE交付，不涉及解析、OCR、分类、课时或Excel写入。

## 第1轮：源码差异审查

- 检查点：`gui_app.py`差异是否集中在主题、布局、样式和空状态。
- 发现问题：无业务解析或导出模块改动；UI颜色原先散落。
- 是否修改：是。
- 修改位置：新增集中式 `UI` 设计令牌与 `_build_style` 主题配置。
- 本轮评分：100/100。

## 第2轮：整体布局审查

- 检查点：顶部品牌栏、左侧步骤、右侧结果、底部操作栏是否完整。
- 发现问题：原页面外边距和卡片区分偏弱。
- 是否修改：是。
- 修改位置：`_build_ui` 的页面留白、左右分栏、结果卡片和底栏。
- 本轮评分：100/100。

## 第3轮：顶部品牌栏审查

- 检查点：标题、副标题、流程状态是否清晰且不拥挤。
- 发现问题：标题权重不足，状态与标题层级接近。
- 是否修改：是。
- 修改位置：`AppTitle.TLabel`、`Subtitle.TLabel`、`Flow.TLabel`及Header内边距。
- 本轮评分：100/100。

## 第4轮：左侧Step卡片审查

- 检查点：四步流程、说明、按钮和卡片间距。
- 发现问题：Step 1四个按钮横排时可能截断。
- 是否修改：是。
- 修改位置：四个Step统一14px内边距和12px间距；Step 1按钮改为2×2网格。
- 本轮评分：100/100。

## 第5轮：表单与文件列表审查

- 检查点：模板路径、文件列表、年月、教师和简称的可读性。
- 发现问题：输入框和表格行高偏紧，空材料提示不友好。
- 是否修改：是。
- 修改位置：Entry/Combobox内边距、Treeview行高、材料计数空状态和路径横向滚动。
- 本轮评分：100/100。

## 第6轮：右侧结果区审查

- 检查点：Tab、表头、行高、空状态和日志区。
- 发现问题：初版空状态位于第一列，不够像正式软件。
- 是否修改：是。
- 修改位置：Notebook/Treeview统一样式；空状态改为表格中央覆盖提示；日志改为柔和背景。
- 本轮评分：100/100。

## 第7轮：按钮体系审查

- 检查点：预览、导出、打开、退出、上传和危险操作的主次。
- 发现问题：原按钮视觉等级接近。
- 是否修改：是。
- 修改位置：Primary、Success、Secondary、Danger、Upload五类ttk按钮样式及禁用态。
- 本轮评分：100/100。

## 第8轮：窗口尺寸与DPI审查

- 检查点：默认1360×860、最小1120×720及125%/150%缩放静态适配。
- 发现问题：窄窗口可能压缩左栏内容。
- 是否修改：是。
- 修改位置：最小尺寸、左侧固定建议宽度、左侧纵向滚动、右侧弹性权重和底栏状态弹性区域。
- 验证：实际启动1120×720窗口，标题、Step、表格、底栏按钮均可见且无重叠。
- 本轮评分：100/100。

## 第9轮：状态反馈审查

- 检查点：空、就绪、处理中、成功和失败状态。
- 发现问题：日志与结果初始空白缺乏解释。
- 是否修改：是。
- 修改位置：预览/排除/汇总居中空状态、日志初始提示；保留原 `flow_var`、`status_var` 和按钮禁用线程逻辑。
- 本轮评分：100/100。

## 第10轮：最终交付审查

- 检查点：正式办公软件观感、源码运行、新EXE、旧EXE备份和截图。
- 发现问题：第一轮只有源码，缺EXE闭环。
- 是否修改：是。
- 修改位置：旧EXE备份；沿用 `gui_app.spec` 唯一一次重打包；启动新EXE确认新版主题。
- 本轮评分：100/100。
